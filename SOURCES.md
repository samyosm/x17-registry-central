# Source formats observed in the local copies

This is an implementation note for the three readers. It describes the supplied copies, not a verified live deployment.

| Source | Persisted output | Reader | Source identity |
| --- | --- | --- | --- |
| VF48 | InfluxDB v2 `run_<run_number>` measurements; tag `VF48_num`; fields include `trignum`, `tstamp`, `livetime`, `wall_clock_ns` and mapped ADC/pattern values. The point time is assigned in the subscriber after its queue. | `InfluxReader` queries `/api/v2/query` for individual fields. | Measurement, exact Influx time, board tag and field. |
| TriggerApp | `trigger_history.json` contains `{version, entries}` and retains at most 200 entries. Each entry has `id`, UTC `timestamp`, `title`, `note`, `tmod`, `maj`, `thresholds`, `masks`, `invert`, and `notes`. `trigger_config.json` stores editor state; `trigger_programmed.json` stores the last programmed baseline. | `TriggerReader` reads all three JSON files. | History entry ID or `current` for each state file. |
| Control room logbook | `data/logbook.db` has `users`, `condition_events`, and `condition_snapshots`. Events carry `id`, `public_id`, `timestamp`, `category`, JSON `payload`, `comment`, active flag and operator link. Snapshots have `valid_from`, `valid_to`, and JSON `state`. | `LogbookReader` reads all three tables through a read-only SQLite connection each poll. | Table and integer row ID. |

TriggerApp and logbook records retain raw and processed copies; their processor currently leaves data unchanged. Edits to an old JSON entry or logbook row create another revision. VF48 field points are stored once in `detector_points` with their Influx time, measurement, board tag, field, value, and any other returned tags. The Flux HTTP response is annotated CSV parsed in memory; no CSV file is stored. The reader filters the configured `X17_INFLUX_MEASUREMENT` (`run_80` in the observed setup) before transfer. Existing detector rows in `collected_records` remain readable and are deduplicated against new points by source identity. A completed Influx query advances its checkpoint; an interrupted query is replayed and deduplicated. `X17_INFLUX_START_AT` defines the first time range, and subsequent queries overlap by `X17_INFLUX_OVERLAP_SECONDS`.

Each TriggerApp history entry is treated as the start of a distinct experiment run. Its UTC timestamp is also the `When` value sent to Teams. A run ends at the next history entry's timestamp from the same TriggerApp source instance; the newest run has no end yet. Detector points are associated by the half-open interval `[start, end)`, regardless of the reused Influx measurement name `run_80`. A run with no matching detector points has no detector artifact. Otherwise, the API generates CSV and JSON downloads from stored points on request. The TriggerApp entry ID identifies the run because the Influx run number is not unique. This is an operational convention, not evidence that acquisition actually stopped at that instant. Beam state and experiment identity remain unknown. No ADC-to-MeV calibration is available in the inspected source, so the processor does not invent one.

The copied TriggerApp history is capped. A poller cannot recover entries that disappeared between polls unless another source such as the app's backup files is added. The current reader does not import those backups. The Influx reader targets the documented v2 API and needs deployment values in `.env`; it has not queried a laboratory server.

`backfill-influx` uses the same read-only Influx query as the periodic poller but has a separate reverse checkpoint. It begins at the newest data and, with `X17_INFLUX_BACKFILL_RUNS_ONLY=true`, stops at the first retained TriggerApp start or `X17_INFLUX_START_AT`, whichever is later. It queries the previous matching `run_<number>` point to skip empty intervals. A bounded writer thread commits detector batches while the reader fetches subsequent batches. The configured SQLite `synchronous` mode and `temp_store=MEMORY` apply only to backfill writer connections; WAL mode was already enabled. It prints the current time window, records saved, elapsed time, read/write timings, and percentage of the selected time range scanned; this percentage is not a count of imported records. An interrupted Influx stream is retried from its unchanged reverse checkpoint with a smaller query window. All submitted batches finish before the window checkpoint advances, so replay after a failure is safe. When it completes, the forward poller checkpoint advances to the backfill's initial upper bound so regular polling can pick up subsequent points. Run only one of backfill or periodic polling at a time. Historical points outside retained TriggerApp start/end intervals remain unassigned to a displayed run.
